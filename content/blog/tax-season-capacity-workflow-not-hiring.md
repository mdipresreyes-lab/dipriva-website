## Canopy runs intake to delivery in one workflow

On November 3, 2026, Canopy announced general availability of Tax Workflow Automation. Canopy, the all-in-one practice management software designed to help accountants build an autonomous firm, today announced general availability of Tax Workflow Automation, an AI-powered suite that takes tax work from the first document request to the signed, paid return in one connected workflow.

That sentence is the whole product claim, and it is also the whole management question. A workflow that runs from first document request to signed, paid return still needs a firm to set the steps, name the owners, and set the dates. The tool connects the steps. It does not decide them.

With new task-template automations, firms can now send every client a personalized questionnaire and document checklist in bulk, ending the long-standing tradeoff between scale and a personal client experience. A firm sets up intake once in a task template and applies it to hundreds of clients at a time. Canopy then generates a questionnaire and document checklist tailored to each client and sends it automatically when the workflow reaches the right step. That bulk step matters, because intake is where most tax seasons stall, and a personal questionnaire sent by hand to each client does not scale.

With the suite, firms can replace up to five separate tax-season tools: organizers, document requests, return delivery, e-signature with identity verification, and payment collection. Fewer tools means fewer places to check, fewer exports to reconcile, and fewer logins for staff and clients. It does not mean fewer controls. The controls move into the one workflow, and the firm still needs to name who checks each step.

## Capacity breaks on chasing documents, not demand

Most tax firms do not lose tax season to a lack of clients. They lose it to document chasing. A client sends a partial set of documents, then a second set, then a corrected set. A preparer waits for a missing form. A reviewer opens a return and finds no note about which document supports which figure. The return goes back for a missing form. The queue grows, the reviewer becomes the bottleneck, and the firm answers the capacity question with headcount, overtime, or a hard stop on new clients.

That pattern is a workflow failure, not a talent failure. The firm has the expertise to prepare, review, and sign. It lacks a fixed intake order, a fixed chase rule for missing items, a fixed review queue with one owner, and a fixed delivery step with signature and payment. Without those four pieces, every return becomes a custom job, and custom jobs do not scale in a fixed season.

Hiring does not fix that pattern. A new hire joins the same broken queue, with the same missing documents and the same unclear flags. The firm pays a full salary for a person who leaves after the season, and the queue is still broken the next year. Capacity grows only when the intake, the prep, the delivery, and the sign-off step grow together. That is the workflow this post builds.

## Workflow capacity means fixed steps, not more staff

Workflow capacity is a precise claim, and a firm should hold any tool to it in three parts.

First, fixed intake. Every client gets a questionnaire and a document checklist tailored to that client, sent when the workflow reaches the right step, not when a staff member remembers to send it. The checklist names the documents, the due date, and the owner who chases a missing item. If intake has no fixed order, the rest of the workflow has no clean input to work with.

Second, fixed prep. Client documents go to the prep step in one flow, with the return populated inside the system the firm already runs, not in a separate tool that needs a second export. The prep step needs a rule for what counts as ready to review, who clears each flag type, and what happens when a flag cannot be cleared from the documents on file. Without that rule, flags become noise, and reviewers learn to ignore them.

Third, fixed delivery. The finished return goes to the client in a guided flow, the client reviews it, signs, and pays, and the firm can require payment before the return is released. That delivery step is part of capacity, because a return that is prepared but not signed and not paid is still work in progress, and work in progress still takes staff time to chase.

As an illustration, not a client result and not a statistic: a tax firm sends one bulk intake template to its clients, chases the one missing form per client on a fixed date, sends the reviewer a return with a short flag list, and sends the client a guided delivery flow for review, signature, and payment. The reviewer clears the flags, signs, and the return moves out. The illustration is useful because it shows the workflow, not because it promises a result. The result comes from repetition, and repetition comes from a written workflow with an owner.

## Smart Intake, Smart Prep, and Smart Delivery explained

The Canopy suite has three connected modules, and each one covers one part of the workflow.

Smart Intake generates client-specific questionnaires and document checklists and recognizes, renames, and files uploaded documents. The intake step is where the firm sets the template once and applies it to hundreds of clients at a time. That is the step that ends the choice between sending one standard organizer to every client and building each questionnaire by hand.

Smart Prep sends client documents to integrated AI preparation partners, which populate returns inside the workflow. The prep step is not Canopy preparing the return itself. It is Canopy sending the documents to a preparation partner and bringing the populated return back into the one workflow, so the reviewer works in one place.

Smart Delivery reads the finished return and builds a guided flow in which clients review the return, sign the 8879, and pay their invoice. Firms can require payment before the return is released. That payment step matters for capacity, because a firm that releases returns before payment collects later, chases later, and carries the cost of the season longer.

Those three modules work only as one workflow. Intake without a fixed prep step produces more documents for the same broken queue. Prep without a fixed delivery step produces more returns for the same broken signature chase. Delivery without a fixed intake step produces a clean signature flow for returns that arrived late and incomplete. The firm needs all three, with a named owner for each, or the workflow stalls at the missing step.

## Per-client credits change the cost question

Canopy does not price Tax Workflow Automation by the return. It prices it by the client credit, starting at $34 per credit per client on annual billing, with volume discounts available. Each credit gives you unlimited use for one client for the rest of your subscription term. One credit per client covers unlimited AI intake and deliveries for that client for the subscription term, including extensions and re-deliveries.

That pricing sentence changes the buying decision for a small or mid-sized firm. The firm does not need to guess the cost of the workflow after the season. It knows the cost per client before the season starts, and it can count its clients and set a budget. The firm should check the current Canopy terms before it buys, because prices and volume discounts change, and the base practice management subscription is separate from this add-on.

That change does not remove the price question. It moves the price question to the right place. The firm still needs to know the prep partner cost, the review time per return, and the fee per return, and it still needs to set those numbers before the season. A tool that costs a known amount per client and still leaves the review queue broken saves intake time and keeps the bottleneck.

Fixed-price per-return prep, in this post, means the firm sets its own fixed price per return before the season starts. The firm knows the Canopy cost per client, knows the prep cost per return, and sets one fixed price per return for its clients. That fixed price is the capacity plan. It tells the firm how many returns it can take, how many reviewers it needs, and what it earns per return, before it hires anyone. Headcount is one answer to a capacity gap. A fixed intake order, a fixed prep rule, a fixed delivery flow, and a fixed price per return are other answers, and they cost less than a hire that leaves after the season.

## Seven steps that turn workflow into capacity

1. Audit intake and list only the document types, channels, and tax system the firm will use each week. Close or leave out the rest, so maintenance stays small.
2. Set one intake template with a questionnaire and a document checklist per return type. Fix the template before the season starts, so every preparer and every client uses the same order.
3. Set a missing-document chase with a fixed date and a fixed owner. A return does not enter the review queue until its documents are complete, or until the missing item has a named next action.
4. Send the reviewer a return with a short flag list. Write the flag rule in advance: what counts as a flag, who clears each flag type, and what happens when a flag cannot be cleared.
5. Run one review queue with one owner per return. The reviewer clears flags, checks traced figures, and signs, in that order, with no return skipping the queue.
6. Run delivery, signature, and payment in one guided flow. Require payment before the return is released, and chase only the returns that stall at that step.
7. Write the workflow down, set the fixed price per return, train the team, and review it after the first 2027 batch. Correct the workflow where returns stall, then hand it to the named owners with dates.

That list is the whole capacity plan in miniature. It does not require a new department, a new hire, or a new stack of tools. It requires clean inputs, a fixed prep step, a fixed delivery flow, and a written workflow. Firms that complete those seven steps have a capacity plan they can run.
